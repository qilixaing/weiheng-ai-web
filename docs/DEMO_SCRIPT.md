# 维衡 AI 现场演示脚本（约 4 分钟）

## 演示前准备

1. 在项目根目录配置服务端 `.env`；不要在前端或浏览器存储中放密钥。
2. 运行 `npm run typecheck`、`npm test` 和 `npm run build`。
3. 启动 `npm start`，浏览器打开 `http://localhost:4173`；通过 `/api/ai/status` 核对 `configured` 为 `true`。修改 `.env` 或服务端代码后重启 Node 服务。
4. 准备演示用的合成档案和一条专用饮食记录；不要展示真实姓名、个人备注或其他人的照片。
5. 如需演示照片识别，单独选择明确可用于演示的图片，并告知画面会发送给 DeepSeek。

## 流程

### 0:00–0:40：说明问题与数据边界

进入“食物浏览”或“饮食记录”，搜索“白菜”并打开“大白菜（生）”详情。展示 USDA 样本名称、每 100 克可食部口径、来源版本和主要营养指标。指出生白菜、水煮白菜、小白菜和卷心菜是不同条目；没有来源的泛称不会用相似食物冒充精确数值。

### 0:40–1:50：展示 Agent 检索和工具轨迹

进入“膳食方案”，输入“帮我搭配一份包含蔬菜和主食的简单午餐”，生成待确认方案。可以先保持个人上下文选项未勾选，说明档案偏好默认不会发送；若演示个性化，再明确勾选后生成。展开“查看 Agent 检索与工具调用依据”，依次说明：本地目录搜索、条目详情读取、程序按可食部克数计算、与档案目标比较。核对条目来源、缺失指标、模型和数据版本。强调模型只整理建议，营养数字来自本地目录和程序，方案尚未保存。

### 1:50–2:20：让用户确认方案

修改一项食物克数，说明份量变化会重新按数据计算。点击“确认并加入饮食草稿”，再打开“饮食记录”检查这批食物；指出确认只加入当前草稿，仍由用户决定何时保存。

### 2:20–3:20：保存并查看每日报告

检查日期、餐次和克数后保存当天记录。打开“AI 营养分析”，先看程序计算的小计和缺失范围，再看 AI 对记录范围、食物搭配和调整建议的解释。说明 AI 估算项始终与数据库实值分开标注，记录与报告保存在本地浏览器，分析请求发送必要的食物条目、克数、计算汇总与所需目标。

### 3:20–4:00：展示失败恢复

演示环境可临时使用一个无效/未配置的测试服务端配置，保存记录后查看分析失败提示，再恢复有效服务端配置并点“重新分析”。确认已保存的饮食记录仍在，报告状态从失败更新为完成。不要故意消耗额度来触发限流或余额错误；这些错误由 mock 测试展示。

## 演示后验证

可在服务启动后运行 `npm run ai:smoke` 检查真实 API 链路；该命令会调用真实模型并消耗额度。照片项只有显式运行 `node .\scripts\ai-smoke.mjs --image <演示图片路径>` 才会执行。不运行真实冒烟时，应将模型验证表述为 mock 协议验证，不说成已实测真实模型。
