# 维衡 AI｜线上评审说明

## 项目要解决的问题

日常饮食管理常遇到三个断点：食物名称相同但品种或熟制状态不同；营养数据的来源和口径不清楚；一般性的 AI 建议难以回到具体食物和实际份量。维衡 AI 把食物查证、份量记录、营养计算和解释放进同一个浏览器应用，让用户能检查依据并保留确认权。

## 评委可直接检查的产品路径

1. **食物浏览与查询**：从侧边栏进入“食物浏览”，搜索白菜、鸡蛋或其他常见食物，打开详情核对品种、生熟状态、每 100 克可食部、原始来源和缺失指标。多个相似条目会保留区别，不以相似食物的营养值替代缺失数据。
2. **餐食规划 Agent**：进入“膳食方案”，提交一个自然语言目标。服务端 Agent 使用注册的食物检索、详情读取、营养计算和目标比较工具；检查工具轨迹和数据证据，修改克数后确认方案。
3. **饮食记录**：在“饮食记录”复核食物、份量、餐次和日期后保存。未确认的 Agent 结果不会自动覆盖记录。
4. **每日营养报告**：报告先展示程序算出的已知摄入，再展示 AI 的文字解释和单独标记的估算范围。更新记录后，旧报告会显示需要更新；分析失败不撤销已保存记录。

## AI 与数据的职责边界

- 食物营养数据库是可核验食物条目和每 100 克可食部原始值的唯一来源。缺失值保持缺失；真实零值与暂无数据分开表示。
- 克数换算、营养汇总和已知目标差值由应用程序计算。AI 不负责这些精确数值。
- Agent 的工具在服务端白名单中注册，模型只能查询、读取和计算；它不能直接保存或修改用户饮食记录。
- 照片识别需要用户主动拍照或选择图片，并在 UI 中提示图片会发送给 DeepSeek。照片识别只提供候选食物和份量估算，用户仍要核对。
- 模型请求经 Node.js 服务端发送；API 密钥只存在服务端环境。饮食记录、草稿和报告按当前产品设计保存在浏览器本地。每日分析不发送照片和备注。

## 数据审计快照

- 食物目录版本：`USDA-SR28-2016-05-curated-146-v2`
- 合并目录：189 条、20 个分类；其中 146 条有来源 ID、版本和链接。该统计可用 `npm run food:audit` 复现，逐指标缺失情况和代表食物见 [FOOD_DATA_COVERAGE.md](FOOD_DATA_COVERAGE.md)。
- 这是一份精选目录，不覆盖所有中国本地品种、品牌、配方或烹饪方式。无精确来源的条目保留“暂无数据”；AI 估算不会写进数据集。

## 工程与验证入口

- Vue 3 + Vite 前端；Node.js 服务端集中处理 AI 请求和密钥。
- TypeScript 对 Vue SFC、领域类型和 Agent 接口执行 `vue-tsc --noEmit`；服务端共用的 JavaScript 营养计算与存储模块保留 Node 可直接导入的形式，并由文件级检查覆盖。
- `npm test` 使用 mock 验证协议、数据处理和错误路径，不需要真实 API 密钥。
- `npm run ai:smoke` 单独访问本机 `/api/ai/*` 并调用服务端配置的模型；它会产生真实模型请求，未配置或失败时如实返回失败。真实调用状态记录见 [AI_EVALUATION.md](AI_EVALUATION.md)，不得将 mock 通过描述为真实模型通过。
- 可重复的产品讲解顺序见 [DEMO_SCRIPT.md](DEMO_SCRIPT.md)。线上评审无需现场操作员讲解，可直接从应用的“作品说明”页面进入各功能。

## 本地复核

需要 Node.js 22.17 或更新版本。复制 `.env.example` 为 `.env`，仅在服务端配置 DeepSeek 环境变量，然后执行：

```powershell
npm install
npm run typecheck
npm test
npm run build
npm start
```

浏览器打开 `http://localhost:4173`。若暂不配置模型密钥，食物浏览、营养计算和本地记录仍可检查；AI 功能应显示真实的未配置状态。
