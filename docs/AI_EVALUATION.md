# AI 质量验证

本页区分了自动化协议测试与真实模型冒烟测试。mock 测试验证服务端边界、输入校验、错误状态和恢复行为；它不能证明真实账号、模型能力或回答质量。真实冒烟测试必须单独执行。

## 本地 mock 测试

~~~powershell
npm test
~~~

`tests/ai-api.test.mjs` 为服务端注入模拟上游，不会访问 DeepSeek，也不需要密钥。覆盖食物检索依据、每日营养由程序重算、照片识别结构、Agent 白名单工具与用户确认边界、提示注入和无 Function Calling 支持时的失败状态、无效估算拒绝、截断响应重试，以及上游失败后对同一分析请求重试成功。

`tests/ai-smoke.test.mjs` 使用本机临时 HTTP fixture 验证冒烟脚本会只访问 `/api/ai/*`、记录结构与状态、将未提供图片标为跳过、处理显式图片输入、保留真实错误分类并隐藏测试密钥。这仍是脚本测试，不是 DeepSeek 实际调用。

## 真实本地服务冒烟

先在终端 A 启动项目服务：

~~~powershell
npm start
~~~

在终端 B 执行：

~~~powershell
npm run ai:smoke
node .\scripts\ai-smoke.mjs --image .\path\to\synthetic-meal.jpg
~~~

脚本只接受 loopback 本机地址。默认地址为 4173；其他端口可先在 PowerShell 设置 `$env:AI_SMOKE_BASE_URL='http://127.0.0.1:4174'`，再运行脚本。服务端必须已从 `.env` 或进程环境读取 `DEEPSEEK_API_KEY`。脚本不读取密钥，向本地服务器发送的内容只有合成餐食问题、合成档案、合成食物克数和项目目录 ID；照片识别只在显式指定 `--image` 时包含该图片。

检查项包括服务状态、食物问答、餐食规划 Agent 和每日营养分析。传入图片时增加照片识别检查；不传图片会显示 `SKIPPED`，不记为通过。每项输出 HTTP 状态、耗时、实际响应模型、食物数据版本和响应结构校验结果。Agent 必须成功返回已完成的四项白名单工具轨迹和待确认方案；Function Calling 不可用会以接口错误报告。HTTP 错误仅显示项目服务端返回的错误码和用户可读原因，脚本不会打印请求头或原始上游响应。

真实调用会消耗少量 DeepSeek 额度，建议只在需要验证服务配置或准备演示时手动运行。不要为了验证错误路径而重复触发限流或余额不足；这些情况由 mock 测试覆盖。

## 失败分类

| 结果 | 含义 | 处理方式 |
| --- | --- | --- |
| `NOT_CONFIGURED` | 服务端未读到有效密钥 | 配置服务端 `.env` 并重启服务；不要把密钥放入 Vite 前端变量 |
| `AUTH_FAILED` | 上游拒绝鉴权 | 在服务端检查密钥是否有效、是否误带空格 |
| `INSUFFICIENT_BALANCE` | 账户余额或可用额度不足 | 检查账户额度后再运行 |
| `RATE_LIMITED` | 上游限流 | 等待服务恢复，不以重复请求测试限流 |
| `TIMEOUT` / 网络错误 | 上游请求未在期限内完成或网络不可达 | 检查本机服务网络与 DeepSeek 可用性，稍后重试 |
| `TOOL_CALL_UNSUPPORTED` | 当前模型或配置没有完成要求的 Function Calling | 选择支持该调用方式的服务端模型；不可将普通文本回答视为 Agent 通过 |
| 结构校验失败 | HTTP 成功但返回数据缺字段或工具轨迹不完整 | 保留该失败证据，检查模型配置/响应兼容性，不伪报通过 |
