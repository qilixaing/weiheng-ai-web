# 聊天同步与文档导出修复（2026-11-06）

## 使用

登录同一个账号后，文字对话继续按账号同步。自动建立的本机空对话不再遮住其他设备的已有消息。助手右上角“更多 → 历史对话”可切换不同日期的聊天；主动点击“新对话”仍会保留用户的新会话选择。

打开助手、切换日期或会话时，默认定位到最新消息。上翻查看历史后暂停自动跟随；离开底部超过 64 像素时，在输入区上方显示向下箭头，点击回到最新消息，回到底部后自动隐藏。在底部时继续跟随流式回复、图片或文件按钮引起的内容高度变化。导航隐藏再显示、窗口大小变化也会重新计算，避免工作台初始隐藏导致默认滚动失效。

明确要求 PDF、Word 或长图时，先直接显示计划正文，正文下方依次显示 PDF、Word、长图三个操作按钮，不再折叠正文或其他格式。最新回复自动生成用户请求的格式；其余格式和旧消息按需生成。下载链接只在真实文件生成后出现，点击时无需再异步生成。普通聊天和未明确要求文件格式的回复不显示任何“导出”入口或文件按钮；显示条件仅依据对应用户提问，不依据助手自行提及的文件格式。格式包括 PDF、Word（真正的 DOCX 文件）和 PNG 长图。生成文件不重新调用 AI、不另行编造营养数值，也不把聊天正文发送给第三方文档服务。较长 PDF 自动分页；超长图片分张后打包为 ZIP。导出器按需加载，不加入首次启动的依赖图。

历史聊天原文保留。文件正文输出模式明确要求模型直接完成正文，不沿用旧历史中的“无法生成文件”。文件视图和导出会去除仅讨论文件能力的过时开头；若开头涉及身体指标、营养限制或安全信息，则完整保留。只有拒绝文字而没有正文时，不会假装生成成功，会提供重新生成入口。

文档请求单独使用 6000 token 输出限额与 24000 字符流式长度上限；普通聊天仍使用原限额，避免长计划沿用短回复限制而被截断。最终正文事件与展示、文件使用一致的内容。

## 同步处理

- 本地写入合并已同步但尚未展示的其他线程，避免旧界面状态覆盖它们。
- 正在本机回复时延后应用远端更新，回复结束后补合并，不丢弃通知。
- 完成回复立即尝试同步；请求期间又产生新数据时保留待同步状态。
- 页面离开前先保存最新本机消息，再发送同步请求。
- 保持游客、不同账号和附件本机存储隔离，保留已有消息及删除标记。

## 实际验证

- 构建与类型检查通过；124 项测试通过。
- 新增客户端测试使用隔离的模拟手机、电脑和其他账号，覆盖读取与上传、空线程显示、并发编辑保留、离线重试、账号隔离和离开页面前保存。服务器网络由合成适配器模拟，未读取真实用户对话。
- DOCX 用 ZIP/OOXML 检查确认真实 Word 结构、中文表格、特殊字符转义和无宏/外部关系；未在 Microsoft Word 内实机打开。
- PDF 使用生产导出器生成，并由 PDF.js 解析页数及页面指令；Poppler 渲染出的中文表格图片已目视检查。PNG 同样由生产导出器生成并检查。
- 服务端文档能力与长正文先通过模拟 AI 响应测试。随后在桌面主项目实际调用现有 AI 一次，仅发送“导出功能验证”合成短请求，不含身体档案、饮食记录或真实聊天内容；实际回复成功生成 72,591 字节的有效 PDF。本轮没有邮件调用。该短请求验证不等同于真实用户完整一周计划质量或手机原生下载实测。
- 使用实际 Vue 文件卡片的组件生命周期和合成画布，验证截图中的原句触发自动生成、显示直接下载链接，且链接可读取真实 PDF 字节；同时验证超过普通聊天长度的文档流式响应完整返回、原有身体及安全说明不会被误删。该检查不是手机浏览器原生下载操作实测。
- 滚动测试使用模拟几何尺寸和 Vue 生命周期，覆盖首次定位、流式跟随、历史阅读保护、向下箭头状态、回到底部、初始隐藏再激活、切换会话及异步内容高度变化；不将这些模拟测试当作真实手机操作实测。

## 限制

PDF 使用图片页面以保证中文显示，不提供可选中的文字层；需要编辑正文时使用 DOCX。手机浏览器的实际下载/保存交互尚未实机验证。聊天附件文件仍在原设备，跨设备可同步文字与附件元数据；导出文件可从已同步文字重新生成。断网或浏览器关闭前来不及完成上传时保留本机副本，恢复网络或再次打开后继续同步。

本轮为本地修复，发布与 GitHub 上传需单独执行，不能将本地测试当作线上更新。
